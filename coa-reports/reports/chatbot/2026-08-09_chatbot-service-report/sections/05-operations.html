AWS 계정이 바뀔 때

AWS 계정은 저장소처럼 소유권 버튼 하나로 이전되지 않습니다. 새 계정에 인프라를 만들고 데이터를 복사한 뒤 트래픽을 전환하는 병행 구축 방식이 가장 안전합니다. 가능하면 AWS 계정 이전과 도메인 변경을 같은 날 동시에 하지 않고, 새 인프라를 기존 주소로 먼저 검증한 다음 주소를 변경합니다.

AWS 계정 이전 시 자원별 작업
자원새 계정에서 할 일전환 시 주의사항
IAM·결제회사 소유 계정, MFA·관리자, 비용 알림과 n·Xavis 연동 여부를 먼저 준비하고 EC2에는 S3 최소 권한 IAM Role을 부여합니다.root·개인 장기 Access Key로 운영하지 않습니다. 새 계정번호와 비용 조회 경로를 보고서에 갱신합니다.
네트워크VPC·subnet·route·security group, 고정 IP 또는 load balancer와 HTTPS 종단을 재구성합니다.RDS는 앱에서만, SSH는 승인된 경로에서만 접근하도록 하고 새 public endpoint를 DNS 전환 전에 시험합니다.
EC2AMI 공유/복사 또는 새 서버 구축 후 Python·Node·systemd·작업폴더와 self-hosted runner를 설치합니다.새 PEM/SSM 접속, chatbot.service, runner online, 디스크 경로·권한을 검증합니다. 기존 PEM은 새 계정 자원에 자동 승계되지 않습니다.
RDS이관 직전 manual snapshot을 만들고 새 계정에 공유·복사·복원하거나 승인된 DB migration을 수행합니다.암호화 snapshot 공유에는 KMS 공유·복사가 필요하며 AWS 관리형 키로 암호화된 snapshot은 그대로 공유할 수 없는 제한이 있습니다. 새 endpoint로 DATABASE_URL을 교체합니다.
S3새 bucket에 document-chatbot 전체 객체를 cross-account copy/sync하고 destination bucket 소유권·암호화·versioning을 설정합니다.객체 수·용량·checksum 또는 표본을 대조하고 새 계정이 객체 소유권을 갖는지 확인합니다. AWS_S3_BUCKET을 교체합니다.
비밀정보ENCRYPTION_KEY는 정확히 유지하고 새 RDS·S3·AWS 자격정보를 GitHub Secrets에 등록합니다.최소 변경 대상은 DATABASE_URL, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_S3_BUCKET입니다. IAM Role 적용 후에는 장기 AWS 키 제거를 검토합니다.
검색 인덱스S3의 기존 FAISS를 복사하되 새 환경에서 승인 문서 전체 재인덱싱을 1회 수행합니다.RDS 문서 상태, S3 원문과 EC2 인덱스가 같은 시점인지 확인하고 대표·회귀 질문을 실행합니다.
DNS·배포새 EC2 runner 배포가 성공한 뒤 DNS를 새 endpoint로 전환하고 TTL 동안 양쪽을 관찰합니다.기존 AWS 계정과 서버는 즉시 삭제하지 말고 합의한 안정화 기간 뒤 백업·로그를 확인하고 종료합니다.
