07

운영 소유권과 담당자 변경

챗봇 소스는 담당자의 개인 GitHub 저장소에서 관리합니다. 담당자가 바뀔 때는 새 저장소 복제보다 GitHub Repository Transfer를 우선합니다.

평상시

차기 담당자를 collaborator로 미리 등록하고, 코드와 관리자 운영을 최소 2명이 이해하도록 합니다.

담당자 변경 시

저장소 전체를 차기 담당자의 개인 GitHub 계정으로 이전해 커밋·이슈·설정의 연속성을 유지합니다.

이전 후

GitHub Secrets, EC2 runner, 서버 작업 폴더의 origin과 첫 배포를 차례로 확인합니다.

빠른 이관 체크리스트

  1. 차기 담당자의 저장소·AWS·OpenAI·Google·EC2 접근 권한을 먼저 확인합니다.
  2. RDS 백업, S3 데이터와 ENCRYPTION_KEY의 복구 가능성을 확인합니다.
  3. GitHub Repository Transfer를 실행하고 차기 담당자가 수락합니다.
  4. Actions Secrets와 self-hosted runner 상태를 확인합니다.
  5. EC2와 개발 PC의 origin을 새 저장소 주소로 변경합니다.
  6. 첫 배포 후 사용자 채팅, 관리자 로그인, 문서 검색과 상담 연결을 점검합니다.
  7. 모든 확인이 끝난 뒤 기존 담당자의 권한을 정리합니다.

비밀정보 발급·인계·등록 방법

13개가 모두 암호키인 것은 아닙니다. 현재 deploy.yml이 GitHub Actions Secrets에서 읽는 값이 13개입니다. 이 중 실제 비밀·접속정보는 7개, AWS 자격 증명 식별자는 1개, 공개돼도 인증 자체가 깨지지는 않는 운영 설정값은 5개입니다. 한곳에 등록한 이유는 배포 때 서버와 프론트엔드 환경파일을 자동으로 만들기 위해서입니다.

가장 중요한 구분: ENCRYPTION_KEY는 새로 발급받는 외부 서비스 키가 아닙니다. 운영 중인 정확한 기존 값을 안전하게 인계받아야 하며, 이 값 없이 새 키를 만들면 기존에 암호화된 대화·FAQ·프롬프트·문서 데이터를 읽지 못할 수 있습니다. 반면 OpenAI·AWS·LangSmith 키는 새 담당자 권한으로 재발급하고 검증 후 기존 키를 폐기할 수 있습니다.

PEM 키와 EC2 접속권한 이관

PEM은 무엇이며 왜 별도인가

PEM은 Linux EC2에 SSH로 접속할 때 사용하는 개인키입니다. 애플리케이션이 실행될 때 읽는 13개 값이 아니므로 GitHub Secrets에 넣지 않습니다. AWS는 private key 사본을 보관하지 않기 때문에 분실한 같은 PEM을 다시 내려받을 수 없습니다.

권장 인계 방식

기존 PEM 파일을 여러 사람이 공유하지 말고, 차기 담당자가 새 key pair를 만들게 합니다. 기존 담당자가 접속 가능한 동안 새 공개키를 서버의 ~/.ssh/authorized_keys에 추가하고 새 키 접속을 확인한 뒤, 최종 검증 후 기존 공개키를 제거합니다.

PEM 전환 순서: 새 key pair 생성 → private key를 차기 담당자의 승인된 금고에 저장 → 기존 접속으로 새 public key 추가 → ssh -i <new-key>.pem <user>@<host> 접속 시험 → 새 키로 sudo·서비스 로그·runner 상태 확인 → Session Manager 같은 비상 접속수단 확인 → D+7 이후 기존 public key 제거. 새 접속이 검증되기 전에는 기존 키를 먼저 제거하지 않습니다.

AWS 권장 방향: AWS는 EC2에서 장기 Access Key를 저장하는 방식보다 IAM Role의 임시 자격 증명을 권장합니다. 가장 빠른 이관은 현행 키 구성을 먼저 정상화하는 것이지만, 후속 보안 개선에서는 EC2 instance profile에 S3 최소 권한을 부여하고 AWS_ACCESS_KEY_ID와 AWS_SECRET_ACCESS_KEY 의존성을 제거하는 것이 좋습니다.

비밀정보 원칙: API 키, DB 접속 문자열과 암호화 키의 실제 값은 이 보고서나 Git 저장소에 기록하지 않습니다. 특히 ENCRYPTION_KEY는 기존 암호화 데이터를 복구하는 데 필요하므로 승인된 비밀 저장소에 별도 보관합니다.
