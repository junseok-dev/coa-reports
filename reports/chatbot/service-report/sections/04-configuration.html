배포와 환경 구성

저장소에는 실제 값이 아닌 .env.example만 포함합니다. 새 운영 환경의 계정 소유자가 자신의 서비스에서 값을 발급·생성한 뒤 새 저장소의 GitHub Actions Secrets에 등록합니다.

비밀값 관리: 저장소와 보고서에는 실제 .env, API 키, DB 비밀번호와 GitHub Secrets 값을 포함하지 않습니다. 운영값은 회사 소유 계정에서 발급해 배포 환경에 직접 등록합니다.

현재 배포에 필요한 GitHub Actions Secrets

필요성, 값을 준비하는 곳과 확인 방법
이름왜 필요한가새 환경에서 값을 준비하는 방법등록 후 확인
OPENAI_API_KEY 질문 분류, 답변 생성과 문서 임베딩 요청을 인증합니다. 회사 OpenAI 계정의 API Platform → API keys에서 운영 Project를 선택해 새 키를 생성합니다. 기존 키의 실제 값은 전달하지 않습니다. 일반 질문, 문서 질문과 문서 재인덱싱이 정상인지 확인합니다.
ENCRYPTION_KEY 대화·보안 정보 등 보호 필드를 Fernet 방식으로 암호화하고 복호화합니다. 신규 DB라면 python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"로 한 번 생성합니다. 외부 서비스에서 받는 키가 아닙니다. 대화 로그와 보안 정보 저장·재조회가 정상인지 확인하고 별도 금고에 원본을 보관합니다.
ADMIN_PASSWORD 현재 워크플로가 보호 환경값으로 주입하는 호환 설정입니다. 주 로그인 방식은 Google OAuth입니다. 운영 환경 전용으로 충분히 긴 임의 비밀번호를 생성하고 다른 서비스의 비밀번호를 재사용하지 않습니다. Google 로그인을 우선 확인하고 이 값은 GitHub와 서버 밖에 노출하지 않습니다.
VITE_GOOGLE_CLIENT_ID 프런트 Google 로그인과 백엔드 ID token 검증이 같은 OAuth client를 사용하게 합니다. 회사 Google Cloud 프로젝트의 APIs & Services → Credentials에서 OAuth 2.0 Web client를 만들고 운영 도메인을 Authorized JavaScript origin에 등록합니다. 배포한 도메인에서 등록된 관리자 이메일로 로그인합니다.
CHANNEL_TALK_URL 사람 상담이 필요한 경우 “상담 매니저 연결하기” 버튼이 열 주소입니다. API 비밀키가 아니라 회사 채널톡 workspace의 실제 상담 주소입니다. 새 저장소에도 같은 회사 상담 URL을 등록합니다. 취소·환불 또는 상담 요청 질문에서 버튼을 눌러 올바른 채널이 열리는지 확인합니다.
DATABASE_URL RDS의 대화, 지식, 설정, 로그와 관리자 데이터를 읽고 저장합니다. AWS RDS에서 만든 DB endpoint, port, DB명과 전용 사용자·비밀번호를 postgresql://USER:PASSWORD@HOST:5432/DB 형식으로 구성합니다. 특수문자는 URL 인코딩합니다. 관리자 로그인 후 조회와 저장, 시스템 상태의 DB 읽기·쓰기 검사를 확인합니다.
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY		 백엔드가 S3 문서와 FAISS 파일을 읽고 쓰는 AWS 요청에 서명합니다. 회사 AWS 계정의 IAM에서 해당 버킷·prefix만 허용한 운영 자격 증명을 새로 만듭니다. 더 안전한 최종 형태는 EC2 IAM Role을 사용해 장기 키를 없애는 것입니다. 문서 업로드·다운로드, 승인 후 인덱스 S3 동기화가 되고 다른 버킷에는 접근하지 못하는지 확인합니다.
AWS_S3_BUCKET 원본 문서, 변환 산출물, FAQ 사본과 FAISS가 저장될 버킷을 지정합니다. 회사 AWS 계정에서 운영용 S3 버킷을 만든 뒤 정확한 버킷 이름을 등록합니다. public access는 차단하고 versioning·암호화를 권장합니다. document-chatbot prefix 아래 파일 생성과 재시작 후 인덱스 복구를 확인합니다.
JWT_SECRET Google 로그인 후 발급되는 8시간 관리자 세션 토큰에 서명합니다. python -c "import secrets; print(secrets.token_urlsafe(48))"로 신규 환경마다 새 값을 생성합니다. 로그인과 관리자 API 호출을 확인합니다. 변경하면 기존 로그인 세션은 다시 로그인해야 합니다.
ADMIN_EMAIL DB에 관리자 목록이 없어도 최초 로그인할 수 있는 최상위 관리자 이메일입니다. Google OAuth로 로그인할 회사 소유 이메일을 정확히 등록합니다. 최초 로그인 후 관리자 화면에서 추가 관리자와 최상위 관리자 설정을 확인합니다.

운영 계정 기준: AWS, OpenAI, Google Cloud와 채널톡은 모두 회사 소유 계정으로 구성합니다. 환경을 새로 만들 때 자격 증명은 재발급하고 채널톡에는 회사 상담 URL을 등록합니다.

Secret 외에 신규 환경에서 반드시 바꿀 항목

현재 소스와 배포 파일에 환경별로 고정된 값
항목현재 위치와 의미신규 환경 작업
EC2 instance IDdeploy.yml의 AWS_EC2_INSTANCE_ID가 코드에 고정되어 시스템 상태 조회에 사용됩니다.새 인스턴스 ID로 바꾸거나 Repository variable/Secret으로 분리합니다.
배포 작업 폴더self-hosted runner가 ~/document-chatbot_practice에서 코드를 갱신합니다.서버에 같은 경로를 만들거나 워크플로 경로를 새 설치 위치로 변경합니다.
AWS region·S3 prefix워크플로가 기본 region과 document-chatbot prefix를 기록합니다.새 AWS 리전과 저장 구조가 다르면 함께 수정합니다.
서비스 도메인·CORS백엔드 허용 origin과 외부 홈페이지 링크 일부가 소스에 포함됩니다.새 도메인, Google OAuth origin, DNS·HTTPS, 홈페이지의 챗봇 링크를 함께 변경합니다.
systemd·runner워크플로는 chatbot.service 재시작과 self-hosted runner 실행을 전제로 합니다.새 EC2에 Python·Node, service unit과 runner를 설치하고 실행 사용자 권한을 맞춥니다.

현재 배포 동작: main에 push할 때 워크플로가 GitHub Secrets로 backend/.env를 새로 만듭니다. 따라서 관리자 보안 정보에서 같은 값을 바꿔도 다음 배포 때 GitHub 값으로 돌아갈 수 있습니다. 현재 구조에서는 재배포 후에도 유지되어야 하는 값의 최종 기준을 GitHub Secrets로 맞춰야 합니다.
