운영 권한 이관

회사 소유 인프라와 운영 데이터는 유지하고 저장소, 자격 증명과 관리자 권한을 새 운영 주체에 연결합니다.

적용 방식: 기존 회사 AWS의 EC2·RDS·S3, OpenAI 운영 Project, 채널톡 workspace와 서비스 도메인은 그대로 사용합니다. 데이터 복사나 새 인프라 구축 없이 운영 권한만 전환합니다.

필수 이관 작업

영역별 작업과 완료 조건
영역작업완료 조건
GitHub 회사 조직에 private repository를 만들고 소스, 환경변수 예시와 배포 워크플로를 등록합니다. main 브랜치에 실제 비밀값 없이 전체 실행 소스가 존재합니다.
회사 계정 AWS, OpenAI와 채널톡에 운영 담당자와 비상 관리자를 등록하고 MFA·결제·보안 알림 권한을 확인합니다. 회사 계정만으로 자원 관리, 사용량 조회와 계정 복구가 가능합니다.
Google OAuth 회사 Google Cloud 프로젝트에 Web OAuth client를 만들고 운영 도메인을 Authorized JavaScript origin에 등록합니다. 회사 이메일로 관리자 로그인에 성공합니다.
GitHub Secrets 기존 회사 자원 연결값과 새 운영 자격 증명을 새 저장소에 등록합니다. 기존 RDS를 사용하므로 ENCRYPTION_KEY는 현재 운영값을 유지합니다. 실제 값이 소스·문서·메신저에 남지 않고 워크플로가 모든 필수값을 읽습니다.
EC2 배포 기존 작업 폴더의 Git remote를 새 저장소로 바꾸고 self-hosted runner를 새 저장소에 등록합니다. 기존 chatbot.service와 도메인은 유지합니다. main push로 배포되고 서비스가 정상 재시작됩니다.
운영 데이터 기존 RDS와 S3를 그대로 연결하고 이관 직전 RDS 복구지점과 S3 versioning·백업 상태를 기록합니다. 대화·문서·FAQ·프롬프트·로그와 FAISS 인덱스가 배포 전후 동일하게 조회됩니다.

설정값 적용 기준

그대로 유지

회사 자원과 데이터 연결

EC2·RDS·S3, DB 연결 대상, S3 버킷·prefix, 채널톡 URL, 서비스 도메인과 기존 데이터용 ENCRYPTION_KEY를 유지합니다.

새로 발급

운영 자격 증명

같은 회사 AWS와 OpenAI 계정 안에서 최소 권한의 운영 자격 증명을 발급해 새 저장소에 등록합니다.

교체

Google OAuth와 관리자 권한

회사 Google Cloud OAuth client와 회사 관리자 이메일을 사용하고 보안 정보 비밀번호를 재설정합니다.

최종 운영 검증

  • 새 저장소의 main push와 GitHub Actions 배포 성공
  • EC2의 chatbot.service 재시작과 /health 정상 응답
  • 회사 Google OAuth 관리자 로그인과 관리자 권한 확인
  • FAQ 질문, 문서 기반 질문과 상담 연결 버튼 확인
  • 기존 대화·문서·FAQ·프롬프트·처리·감사 로그 조회
  • 문서 업로드·승인·FAISS 재구성 후 재배포해도 변경 내용 유지
  • OpenAI Usage와 비용 관리 입력·수정·삭제 확인
  • RDS 복구지점, S3 백업과 Secret 원본 보관 위치 확인
  • 운영 담당자가 단독 배포와 기본 장애 확인을 완료한 뒤 기존 접근 권한 제거

완료 기준: 운영 담당자가 회사 계정만으로 배포, 로그인, 문서 반영, 상담 연결, 로그 확인과 복구 절차를 독립적으로 수행할 수 있어야 합니다.
